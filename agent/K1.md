# K1: host and tools

Run from the repo root with Node 20+:

```sh
node agent/run-local.js "fix the shader banding on mobile"
node --test agent/tests/k1.test.js
```

With `OPENROUTER_API_KEY` set, the CLI uses OpenRouter. `OPENROUTER_MODEL`
overrides `DEFAULT_MODEL` in `host.js` (google/gemini-2.5-flash).
Use `--live` to require credentials, or `--offline` to force the deterministic
fixture. Without a key the CLI explicitly reports offline mode. It never silently
switches to the fixture after a failed live request. Environment variables must be
exported, or loaded using Node's `--env-file` option; this code does not load `.env`.

Web search requires both `ENABLE_EXA=1` and `EXA_API_KEY`. Otherwise its result is a
clearly marked stub with an empty URL and no external evidence. Offline mode always
disables Exa. Model calls time out after 30 seconds by default and retry transport
failures once, including timeouts. HTTP errors and invalid JSON are not retried.
Exa tool failures are handed back to the model without automatic retries.

## Host API

```js
import { runAgent } from './agent/host.js';
import { StubTabSource } from './agent/tab-sources.js';

const result = await runAgent({
  goal: 'your goal',
  tabSource: new StubTabSource(),
  onTrace: event => { /* render or forward the validated event */ },
  env: process.env
});
```

The return value includes `status` (`complete`, `partial`, or `error`), `skill`
(the original validated write_skill payload, or null), `reads`, `iterations`, and
`messages` (including tool results). No Markdown serialization, file writing, or
UI publication happens here. A partial run retains tool results in `messages`.
`model({messages, tools})` and `fetchImpl` can be injected for deterministic tests.
The existing system prompt is loaded from disk unchanged.

The host counts attempted valid read_tab calls, including blocked, unknown, and
failed reads. It executes at most eight reads, even within a single model batch.
Search uses only cached text from successful read responses; unavailable text
produces no excerpts. Batch calls execute sequentially. Following write_skill,
remaining calls in that batch receive error results, then the host returns.

Malformed arguments receive a validation error with one correction opportunity.
The next same-tool invocation is treated as the correction; two consecutive
argument failures disable that tool for the rest of the run. A valid correction
clears the counter. Tool call IDs alone cannot identify a correction, since the
model generates a new ID each turn. Total model turns are capped at 20.
Trace validation and onTrace failures intentionally propagate to the caller.

## Shared-contract integration gap

`MessageTabSource` uses the shared `send` and `on` helpers, with correlation IDs,
reply timeouts, and subscription cleanup. Those helpers cannot await native
sendMessage replies: `send()` discards the return value and `on()` does not expose
sendResponse. Also, the four existing message payloads define no tab RPC.

Consequently the source requires an injected `protocol` with `requestType`,
`responseType`, `encodeRequest({requestId, operation, id})`, and
`decodeResponse(payload)` returning null for unrelated messages or
`{requestId, result, error}` for a reply. The browser teammate must agree and wire
that protocol before this adapter can work with the extension. K1 does not add
message types or repurpose shared payloads. Tests use a test-only codec and an
in-memory bus; that codec is not an extension protocol proposal.

The existing fixtures describe OAuth and Fetch, not shader banding. The offline
fixture is a plumbing exercise that intentionally reads the blocked tab and an
unknown ID, then returns an explicit coverage note. It does not demonstrate live
triage, model judgment, or skill conversion. Initial K1 validation had no OpenRouter key. Subsequent live testing passed
Exa search and content retrieval, plus the OpenRouter loop through a blocked read,
web search, and write_skill (two reads, four model turns). Model date narration
was off by one day; this is a content-quality issue, not a plumbing pass criterion.

API references used: [OpenRouter tool calling](https://openrouter.ai/docs/guides/features/tool-calling)
and [Exa search](https://exa.ai/docs/reference/search).
